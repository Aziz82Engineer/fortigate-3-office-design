One Security Fabric for London, Beirut and Dubai

A complete FortiGate design for a 140-person web and mobile studio: full-mesh SD-WAN over two ISPs per office, MFA-protected remote access for home workers, and ten isolated segments per office. Every config is generated from one inventory file and checked by 220 automated tests.

Topology

Each office pair is joined by four tunnels, one per ISP combination, so any office can lose either ISP and still reach every other office.

Key design decisions

Each choice is tied to a requirement and verified in the test suite.

SD-WAN

Full mesh, not hub-and-spoke

With three offices, a mesh removes the hub as a single point of failure. iBGP on loopbacks carries routes; SLA probes move traffic before a link fails.

Remote access

IKEv2 IPsec instead of SSL VPN

FortiOS 7.6.3 removed SSL VPN tunnel mode. Users sign in with AD over EAP-TTLS plus FortiToken push, and only EMS-compliant laptops can connect.

Segmentation

Ten segments, same plan everywhere

Guests, test phones, printers and cameras never reach staff or other offices. VLAN numbers match across offices; the second octet names the office.

Fail closed

No leaks when tunnels drop

Blackhole routes for all private ranges mean internal traffic is dropped, never sent unencrypted to the internet, if every tunnel to an office goes down.

Inspection

Deep for staff, certificate for developers

Deep SSL inspection breaks Git, Xcode and Android tooling, so developer and lab segments get certificate inspection with IPS, AV and DNS filtering.

Operations

Cloud-managed, nothing on-prem

FortiManager, FortiAnalyzer, FortiClient EMS and FortiIdentity Cloud run the fabric; Beirut runs an HA pair as the Fabric root.

Infrastructure as code, tested
